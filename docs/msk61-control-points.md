# МСК-61: контрольные векторы и границы применимости

## Что проверяется

Файл `packages/offline_geo/tests/data/msk61_proj_control_points.json` содержит
48 векторов (по 16 на каждую зону 1–3). Для каждой точки тест
`test_independent_proj_control_points_cover_all_zones` проверяет:

- прямое преобразование `lat/lon → X/Y` с допуском **0,01 м**;
- обратное преобразование `X/Y → lat/lon` с допуском **2·10⁻⁸°**;
- покрытие всех трёх зон и не менее 20 точек.

Векторы сгенерированы независимой реализацией — системным `PROJ` (`cs2cs`) —
из тех же параметров, что использует приложение:

```text
+proj=tmerc +lat_0=0 +lon_0=<37.98333333333|40.98333333333|43.98333333333>
+k=1 +x_0=<1300000|2300000|3300000> +y_0=-4811057.628
+ellps=krass +units=m
```

Это проверяет **проекционную математику** (формулы Крюгера, масштаб, ложные
смещения, порядок осей X=север / Y=восток). Это **не** официальные кадастровые
контрольные точки и не аттестация датума МСК-61.

## Что не проверяется этими векторами

- Датумная операция профиля `gost_51794_2008` (Helmert Pulkovo 1942 → WGS84).
  Она покрыта тестами обратного преобразования и одним опубликованным
  вторичным примером, но не официальным набором.
- Официальные параметры зон и контрольные точки Росреестра/кадастрового
  округа. Их нужно получить у геодезической организации или из официальной
  методики и заменить/дополнить JSON.
- Точность на местности: высота точки, локальные деформации, реальная
  калибровка. Результат остаётся справочным (`preliminary_unverified`).

## Как добавить официальные точки

Добавьте объекты в `points` с полями `id`, `zone`, `lat`, `lon`, `x`, `y`,
укажите источник в `provenance` и при необходимости увеличьте `tolerance_m`.
Если официальный набор задаёт другую точность, допуск должен следовать
методике, а не подгоняться под текущий результат. Тест подхватит новые точки
автоматически.

Дисклеймер также постоянно показан в UI рядом с калькулятором МСК-61: результат
справочный и не заменяет официальную геодезическую аттестацию.
