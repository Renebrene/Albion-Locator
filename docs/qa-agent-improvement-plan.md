## 2. Подтверждённые замечания — исправить до расширения тестирования

### P1 — Адресный поиск не получает координаты кандидата

**Наблюдение:** `resolveAddressCandidate(query)` определена в `static/index.html:1987–2010`, но у неё нет вызовов. Выбор населённого пункта сбрасывает координаты (`1953–1969`), а ввод улицы/дома также обнуляет координаты (`2023–2027`). `readDraftCoordinates()` в адресном режиме разрешает кнопку только при заполненных `addressLat/addressLon` (`2662–2668`). Поэтому стандартный сценарий «выбрать город → ввести улицу → поставить точку» не может разрешить черновик.

**Действие агента:** связать ввод второго поля с явным геокодированием полной строки `населённый пункт + улица + дом` (например, Enter/blur или отдельное действие «Найти адрес»). Ответ должен только заполнить адресный черновик и показать точность/источник; фиксация точки остаётся отдельным явным действием. Добавить sequence/abort guard, обработать пустую улицу, отсутствие ключа, timeout, 404/out-of-region и повторный ввод.

**Приёмка:** после выбора подсказки населённого пункта и валидного адреса появляются координаты черновика и включается «Поставить точку»; точка, история и `/api/locate` не создаются до явного подтверждения.

### P1 — Онлайн-поиск дорог недоступен, локальный падает при отрисовке

**Наблюдение:** в DOM нет элемента `roadSuggestions` (единственные упоминания — JS `static/index.html:1869,2053,2076,2428`). `setupRoadSuggestView()` определена (`2396–2413`), но нигде не вызывается. `resolveOnlineRoad()` доступна только из обработчика `select` этого неподключённого SuggestView (`2411`). При локальном поиске `searchLocalRoad()` (`2415–2446`) передаёт `null` в `renderSuggestionList()`, который вызывает `container.replaceChildren()` (`1849–1865`) и выбрасывает `TypeError`. Итог: подсказки и выбор трассы онлайн недостижимы, а успешный локальный ответ не может быть показан.

**Действие агента:** вернуть в разметку контейнер подсказок дорог (или переиспользовать один общий `#modeSuggestions` с явным владельцем), инициализировать `setupRoadSuggestView()` после загрузки Yandex API в режиме дорог и добавить null-guard в `renderSuggestionList()`. Развести online и local source: локальный поиск не должен запускаться при выбранном внешнем источнике и наоборот. Убрать второй (дублирующий) обработчик кнопки и опечатку с двойным присваиванием `roadKmState = null`.

**Приёмка:** в режиме «Дороги» ввод `М-4` показывает подсказки, выбор загружает участки, Enter/кнопка применяет км; при отсутствии локальной БД показывается явная ошибка; в console нет `TypeError`/`ReferenceError`.

### P1 — История теряет точки без текстовой метки

**Наблюдение:** UI в `static/index.html:3959–3977` формирует `historyLabel`, который может быть пустым (например, ручная точка без адреса/найденной дороги), затем отправляет его в `/api/history`. Endpoint использует `BookmarkCreate` (`src/main.py:835–839,1926–1931`), где `name` обязателен и имеет `min_length=1`. Запрос с пустым `name` воспроизводимо возвращает `422`; frontend подавляет ошибку в `addToHistory()` (`static/index.html:1257–1265`), поэтому пользователю кажется, что запись истории сохранена, хотя сервер её отклонил.

**Действие агента:** отделить модель истории от модели закладки: `HistoryCreate` с необязательным/пустым label и обязательными конечными координатами, либо формировать безопасную fallback-метку (`lat, lon`/«Точка с карты»). Не менять ограничения API закладок. Добавить успешный endpoint test для пустой метки и UI-flow test для map/coordinate/geolocation.

**Приёмка:** все валидные способы фиксации точки сохраняются в пользовательскую историю; невалидные данные дают понятную ошибку, не скрытую в console.

### P1 — Последняя координата хранится глобально, а не на пользователя

**Наблюдение:** внешний и локальный `/api/locate` записывают `last_point` в общий `src/user_settings.json` (`src/main.py:1178–1181,1298–1304`). Аутентифицированный `/api/screenshot-settings` возвращает весь документ настроек без user scope (`1096–1098`); frontend использует `data.last_point` для центрирования карты (`static/index.html:1615–1617`). Следовательно, разные пользователи приложения могут видеть/восстанавливать последнюю координату друг друга, хотя рабочая сессия и другие данные описываются как персональные.

**Действие агента:** перенести last point в пользовательский workspace/preferences SQLite и прекратить выдавать его из общего endpoint. Миграцию выполнять безопасно: старый JSON не удалять без backup/решения о владельце; не мигрировать общую координату молча всем аккаунтам.

**Приёмка:** два разных пользователя не получают координаты, историю, workspace или preferences друг друга после login/reload; общий screenshot-settings endpoint не содержит координат.

### P2 — Результат преобразования МСК может оставаться устаревшим

**Наблюдение:** `syncCoordsFromWgs()` выставляет `modeInput2` только при `response.ok` (`static/index.html:2797–2806`), но не очищает предыдущее значение перед запросом и не показывает ошибку при неуспешном HTTP-ответе. Backend штатно возвращает 422 при координатах за предварительным доменом зоны (`src/main.py:1790–1804`, пакет `msk61.py`). Пользователь может увидеть старые X/Y рядом с новым WGS вводом и принять их за соответствующие ему.

**Действие агента:** очищать/маркировать поле как «пересчёт…» при новом вводе; проверять `response.ok`, показывать `detail`, отбрасывать stale-ответы и не давать старому X/Y выглядеть как актуальный результат.

**Приёмка:** валидный → вне зоны → новый валидный WGS сценарий всегда показывает соответственно новое значение, явную ошибку/пустое значение, затем новое значение; поздний ответ не перезаписывает новое состояние.

### P2 — Обработчик кнопки режима дорог содержит ссылку вне области видимости и запускает лишний запрос

**Наблюдение:** в обработчике кнопки на `static/index.html:2844–2849` вызывается `applyRoadSearch?.()`, но `applyRoadSearch` объявлена как локальная `const` внутри `setupSearchPanel()` (`3122–3143`) и недоступна внешнему обработчику. Optional chaining не защищает от отсутствующего lexical binding: при клике в режиме дорог первый listener выбросит `ReferenceError`. Кроме того, на ту же кнопку внутри `setupSearchPanel()` повешен второй click-listener (`3143`), поэтому в режиме координат один клик по CRS-кнопке одновременно переключает CRS и пытается запустить дорожный поиск.

**Действие агента:** оставить ровно один обработчик на кнопку, объявить `applyRoadSearch` в общей области видимости или заменить кнопку на отдельные элементы для CRS и поиска. Проверить click/Enter в online/local, armed/disarmed режимах.

**Приёмка:** переключение CRS не делает дорожных запросов; поиск дороги с кнопки и Enter вызывает один запрос/одно действие; в browser console нет исключений.

### P2 — Скриншот вырезается со смещением координат

**Наблюдение:** `finalizeSelection()` получает `rect.getBoundingClientRect()` в координатах viewport (`static/index.html:3626–3645`) и передаёт `rectBounds.left/top` в `ctx.drawImage()` для изображения, полученного из `domtoimage.toPng(document.getElementById('map'))` — то есть в координатах элемента карты. Карта смещена вправо относительно viewport из-за левого фрейма, поэтому вырезается неверная/пустая область. Те же viewport-координаты присваиваются `menu.style.left/top`, хотя меню находится внутри `#map` и ожидает координаты относительно карты.

**Действие агента:** вычитать `mapRect.left/top` (и учитывать масштаб/DPR, если он меняет размер растеризации) при crop и позиционировании меню; либо строить crop от `offsetX/offsetY` внутри `map`. Проверить выделение от каждого края, при разных размерах/зуме карты и при скрытых панелях.

**Приёмка:** сохранённый PNG содержит именно выделенную область карты на любом разрешении и при открытых/закрытых боковых фреймах.

### P2 — Выбор строки batch блокирует обычные двойные клики по карте

**Наблюдение:** `selectBatchPoint()` выставляет `batchEdit.activeId` при обычном выборе строки (`static/index.html:4284–4295`), а обработчик `map.on('dblclick')` блокирует любые точки, если `activeId` задан (`1580–1594`). Режим редактирования не требуется для выбора, поэтому после просмотра batch-точки пользователь не может поставить обычную точку и получает сообщение «Идёт редактирование пакетной точки».

**Действие агента:** отделить «выбранную строку» от «активной редактируемой точки» (например, `selectedId` и `editingId`) либо снимать `activeId` при выходе из edit mode. Блокировать карту только в реальном drag/edit state.

**Приёмка:** выбор строки центрирует/показывает batch-точку, но не блокирует dblclick; блокировка действует только при активном редактировании и снимается Save/Cancel.

### P2 — Повторная загрузка batch скрывает уже показанные маркеры

**Наблюдение:** при `batchEdit.showAll === true` `handleBatchFiles()` вызывает `showBatchPointsOnMap()` (`static/index.html:4276`). Эта функция инвертирует `showAll` (`4390–4397`), поэтому после добавления файлов флаг становится `false`, слой маркеров очищается и новые точки не показываются.

**Действие агента:** заменить toggle-функцию на идемпотентные `renderBatchMarkers()`/`setBatchVisibility(visible)`; после загрузки перерисовывать маркеры при включённом show-all, не меняя флаг. Учесть выбранную/редактируемую точку.

**Приёмка:** при включённом «Показать все» загрузка новой партии оставляет все маркеры видимыми; кнопка не меняет подпись на «Скрыть» сама по себе.

### P2 — Очистка точки не сохраняет workspace; сброс оставляет несогласованный режим

**Наблюдение:** `clearSelectedPoint()` (`static/index.html:3866–3883`) не вызывает `scheduleStateSave()`, поэтому после перезагрузки может восстановиться старая точка. `resetWorkspace()` (`3208–3228`) присваивает `searchDraft.mode = 'coords'` напрямую вместо `setSearchMode('coords')`, из-за чего не обновляются подписи, `aria-pressed`, placeholder и обработчики подсказок. Внутри reset вызывается `clearBatchPoints?.()` с отдельным `confirm`; отмена второго подтверждения не отменяет остальную очистку.

**Действие агента:** сохранять workspace после clear, использовать `setSearchMode()` в reset, собрать одно подтверждение для reset или явно показать область очистки; после reset дождаться DELETE и обновить локальные версии.

**Приёмка:** clear + reload не возвращает точку; reset приводит UI/режим/поля к состоянию по умолчанию; одно подтверждение соответствует фактическому объёму очистки.

### P3 — Скрытый калькулятор МСК-61 и вводящая в заблуждение настройка сохранения

**Наблюдение:** блок `#mskSearchPanel` находится внутри `div hidden` (`static/index.html:807–871`) и не переносится в модальные настройки (переносится только `#geoStatusPanel`, `3297–3302`), поэтому полноценный калькулятор МСК недоступен, хотя описан в README/TECHNICAL_DESCRIPTION. Поле «Папка сохранения на сервере» (`1083`) и POST `save_path` (`1623–1637`) выглядят как серверное сохранение, но фактический `saveImageToOS()` пишет через браузерный file picker/download (`3718–3738`); `/api/save-screenshot` из UI не вызывается.

**Действие агента:** либо перенести панель МСК в настройки/рабочую область и связать с координатными полями, либо убрать её из описания как неактивную. Переименовать/уточнить поле сохранения («файл сохраняется браузером») или реализовать явное серверное сохранение с выбором пользователя; не обещать серверный путь без вызова endpoint.

**Приёмка:** документация и UI совпадают; все видимые настройки влияют на реальный сценарий; недоступные функции не выглядят доступными.

### P3 — Ограничения выбора файлов и информативность ошибок

**Наблюдение:** оба file input принимают `image/*` (`static/index.html:730,777`), но EXIF поддерживает только JPEG/TIFF (`src/main.py:349–364`, `src/batch.py:32–45`). Одиночная загрузка заменяет серверный `detail` общим сообщением (`3897–3918`), batch показывает только количества и не выводит имя/причину отказа по файлу (`4242–4281`).

**Действие агента:** ограничить `accept` до `image/jpeg,image/tiff`, показывать `detail`/per-file error в списке, не терять имя файла при ошибке.

**Приёмка:** неподдерживаемый файл отклоняется с понятным сообщением до/после загрузки; по каждому batch-файлу видно «успех/GPS не найден/формат/лимит».

### P3 — Клавиатура и доступность интерактивных элементов

**Наблюдение:** dropzone (`730`), пункт меню скриншота (`890`), строки истории/закладок (`1277–1291,1326–1339`) и переключатель темы (`1104–1106`) — кликабельные `div` без `button`/`role`/`tabindex`/keyboard-обработчиков. Модальное окно настроек закрывается по Escape, но не удерживает фокус внутри (`3267–3310`). Часть полей аккаунта использует только placeholder (`1116–1137`).

**Действие агента:** использовать семантические `button`/`a` или добавить `role`, `tabindex="0"`, Enter/Space, `aria-label`; реализовать focus trap в модалке; связать подписи `label for`. Проверить tab-порядок и focus-visible.

**Приёмка:** все действия доступны с клавиатуры, фокус не уходит за модалку, у элементов есть доступные имена.

## 4. План регрессионных сценариев UI/API

### A. Авторизация и права

- Вход: правильный/неправильный пароль, повторный вход, logout, истёкшая/отключённая сессия.
- Admin/editor: endpoint пользователей разрешён/запрещён; собственные credentials; серверные mutation routes отклоняют cross-origin.
- Два пользователя: preferences, workspace, bookmarks, history и последняя точка изолированы после logout/login и перезагрузки.

### B. Адрес, координаты, карта

- Адрес: SuggestView отсутствует/ключ отсутствует/таймаут; выбрать город; пустое, частичное и полное поле улицы; geocode success/404/out-of-region; stale response; явное подтверждение; повторный commit не создаёт дубли.
- WGS84: decimal с запятой/точкой/пробелом, lat-lon и lon-lat; DMS N/S/E/W; malformed, NaN, пределы ±90/±180; введённые WGS синхронизируются с выбранной МСК зоной без старого результата.
- МСК-61: зоны 1–3, оба профиля, оба направления, диапазоны и неправильная зона; предупреждение о предварительном качестве; подтверждение перед размещением; 422/timeout/stale responses.
- Карта: dblclick ставит обычную точку; обычный click не должен неожиданно фиксировать точку; включённый search-arm блокирует map/km commit; после подтверждения/отключения режим восстанавливается; геолокация success/permission denied/timeout.
- Граница: внутренняя, внешняя, boundary edge, hole/multipart (если есть), GeoJSON не загрузился. Убедиться, что отсутствие полигона не даёт неконтролируемо подтвердить out-of-region координату.

### C. Дороги и официальный километраж

- Подсказки онлайн: `М-4`, `Р-280`, локальная дорога/код, улица/город/не-дорожный объект, API key отсутствует, WFS/Yandex 404/429/timeout.
- Участки: дорога с километражом, без километража (например, `А-280`), пустые/битые геометрии, sparse vertices, reversed direction, overlapping alignments и gaps.
- Ввод км: `829+500`, decimal, граничные/невалидные/вне диапазона значения; slider preview vs release commit; search-arm должен предотвратить commit; координаты/подпись/маркер/карточка должны соответствовать одному и тому же official km.
- Локальный source без установленной SQLite должен дать явную ошибку и не переключаться на WFS; offline package test не заменяет интеграционную проверку FastAPI ↔ index.

### D. Фото и batch

- EXIF одиночный: корректные JPEG/TIFF GPS, ref N/S/E/W, GPS отсутствует, malformed, oversized, повреждённая картинка; предложение координат не фиксируется до нужного действия.
- Batch: 0/1/N, смешанные валидные/невалидные/без GPS, лимиты 50 файлов / размера файла / размера тела, повторные координаты; показать/скрыть все, выбор строки, rename/delete/clear, выбранная точка и состояние после reload.
- Изменение batch маркера: drag/save/cancel не меняет остальные точки и не инициирует обычный dblclick/locate без подтверждения.

### E. История, закладки, настройки и скриншот

- История для map/coords/geolocation/photo/address/road; пустая метка, delete row/clear all, лимит/порядок, API error, isolation per user.
- Bookmark: add/rename/delete, пустое/длинное имя, ownership, повторный login; кнопки disabled/enabled синхронны с active point.
- Настройки: тема, радиус, категории, источники карты/дорог, локальный data missing, boundary checkbox, screenshot delay (включая выбранную семантику `0`), auto screenshot; persist/reload/user isolation.
- Скриншот: browser picker save/cancel/fallback, серверный валидный/невалидный PNG, filename sanitize/collision; проверить имя `название + км` без даты/стороны; при отмене/ошибке UI полностью восстанавливает скрытые панели/оверлеи.

### F. Общая UI/accessibility/performance

- Проверить каждый видимый `button`, `input`, `select`, checkbox/range: клик, клавиатурный Enter/Space/Escape, disabled/pending, focus/aria status; при смене вкладки/режима состояние не теряется неожиданно.
- Визуально проверить 1920×1080, 1366×768, 1280×720 и 640 px; light/dark; длинные адреса/имена, скролл левого/правого фрейма, status bar, модалки, карта и Leaflet attribution.
- DevTools console/network: ноль uncaught exception; все вызовы same-origin с cookie; ошибки provider понятны; нет дублирующихся запросов на каждый символ/пиксель slider.
### G. Оптимизация и производительность

Приоритет — сначала устранить функциональные дефекты, затем оптимизировать по измерениям, а не по предположениям.

1. **Сетевые запросы.** Проверить debounce для подсказок/координат, отмену устаревших запросов через `AbortController` или sequence guard, отсутствие дублирующих обработчиков (сейчас кнопка режима имеет два listener). Ограничить параллельные `/api/locate` для batch и не запускать locate на каждый ввод.
2. **Карта.** `loadRostovBoundary()` строит boundary mask/line на Canvas; проверить стоимость на слабых машинах, не перезагружать GeoJSON при каждой смене настроек, кэшировать разбор и не создавать повторные слои. `map.on('moveend zoomend', scheduleStateSave)` должен быть debounced.
3. **Персональное состояние.** `scheduleStateSave()` отправляет два документа (preferences/workspace) целиком; проверить debounce/backoff, не сохранять при каждом движении карты, не отправлять неизменённый payload, корректно обрабатывать 409 без циклов.
4. **Backend.** `nearest_road()` в `packages/offline_geo` линейно перебирает геометрии; перед внедрением RTree замерить реальный индекс/объём и сравнить latency/память. `_wfs_getfeature` ограничивает страницы; проверить таймауты/retry и не выполнять повторный внешний запрос при заведомо невалидном вводе.
5. **Память/фронтенд.** Ограничить размер DOM batch-списка, не держать `capturedImageData`/blob после закрытия скриншота (сейчас `clearScreenshotUI()` очищает), проверить утечки listeners при пересоздании SuggestView и модалки.
6. **Наблюдаемость.** Добавить структурированные логи вместо `print` (в `cleanup_old_screenshots` и загрузке базы), метрики длительности `/api/locate` и внешних provider-запросов; не логировать адреса, координаты и секреты. Это позволит обоснованно выбирать дальнейшую оптимизацию.

## 6. Definition of Done

- Адресный поиск заканчивается координатным черновиком; точку можно зафиксировать только явным действием, и история не теряет события.
- Все state/last point/history/bookmarks user-scoped; тесты доказывают отсутствие cross-user leakage.
- В browser console нет runtime exceptions в кнопках/полях; сетевые ошибки и stale responses не показывают старые координаты как новые.
- Километраж согласован между ползунком, вводом, линией/точкой и результатом для непрерывных, разорванных и перекрывающихся участков либо ограничения явно отражены в UI.
- Все тестовые suites зелёные; актуальные тестовые счётчики и порты совпадают в README/техническом описании.
- Основные UI-сценарии проходят browser E2E или документированный ручной checklist на заданных разрешениях; недоступные provider/live сценарии явно обозначены BLOCKED.
- Промпты/LLM не выдаются за активный pipeline без реально вызываемого и покрытого кода.
- Рабочие изменения пользователя сохранены; коммит/push/перезапуск с побочными эффектами — только в рамках явного запроса.
