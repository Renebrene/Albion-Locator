# Изменения 27.10.2026

Продолжение `docs/CHANGES-2026-10-24.md`.

## Исправлено: 502 при установке точки на карту

**Симптом.** Двойной клик по карте → всплывающее «Ошибка сервера 502», справа — «Точка не выбрана. Выберите её на карте или в левом фрейме.»

**Причина.** Поставщик СКДФ убрал слой `skdf_open:lyr_road_by_value_line`: GeoServer отвечает `400 InvalidParameterValue / Feature type ... unknown` на любой bbox. Имя слоя было зашито в `src/main.py`, а `_wfs_getfeature` превращал любой HTTP-сбой в общий 502 — потому падение внешнего слоя выглядело как ошибка приложения. В журнале:

```text
GET .../wfs?...typeNames=skdf_open%3Alyr_road_by_value_line... "HTTP/1.1 400"
{"service":"wfs","outcome":"http_error","retries":0}
POST /api/locate HTTP/1.1" 502 Bad Gateway
```

Проверено: в текущем `GetCapabilities` есть `skdf_open:lyr_road_by_value` с той же схемой (`id`, `road_id`, `road_name`, `start_km`, `finish_km`, `category_gid`).

**Что сделано.**

- `src/main.py`: перебор имён слоя — `ALBION_WFS_ROAD_LAYER` → `skdf_open:lyr_road_by_value` → `skdf_open:lyr_road_by_value_line`; ответ «feature type unknown» отличается от сетевого сбоя, рабочее имя запоминается на процесс и пробуется первым; в ответе указывается фактический слой; если не подошло ни одно имя — 502 с перечнем проверенных и подсказкой про `ALBION_WFS_ROAD_LAYER`. События `wfs_layer_missing` / `wfs_layer_switched` пишутся в журнал.
- `static/index.html`: текст ошибки дополняется серверным `detail`; при сбое поиска дороги правый фрейм пишет «точка выбрана, но дорога не определена: сервис СКДФ недоступен» вместо ложного «Точка не выбрана».
- Тесты: 4 новых (`tests/test_main.py`) — определение «слой не найден», переключение на переименованный слой, сообщение при отсутствии всех кандидатов, приоритет `ALBION_WFS_ROAD_LAYER`. Итого 144 backend-теста.
- Документация: `TECHNICAL_DESCRIPTION.md` (4.2, 4.2.1, новый 4.2.2), `docs/PROJECT.md`, `.env.example`.

**Проверка на живом сервисе.** Точка из журнала (48.238537, 41.400562): было 502 → стало «Автомобильная дорога Р-260 Волгоград — Каменск-Шахтинский — Луганск, 254 км + 187 м, справа по ходу движения, 84 м до оси дороги». С устаревшим именем в `_ACTIVE_ROAD_LAYER` приложение само переключается на `lyr_road_by_value` и продолжает работу.

## Что делать при следующем переименовании

1. Посмотреть в журнале событие `wfs_layer_missing` с именем слоя.
2. Узнать актуальное имя: `.../wfs?service=WFS&version=2.0.0&request=GetCapabilities` и поиск по `road`.
3. Задать `ALBION_WFS_ROAD_LAYER` в `.env` и перезапустить сервис — код менять не нужно.

## Локальная база как осознанный выбор при сбое СКДФ

- При недоступности СКДФ правый фрейм показывает ошибку и — только если локальный индекс установлен и источник ещё внешний — кнопку **«🏠 Показать дорогу по локальной базе»**. По нажатию источник переключается на локальную базу (тот же обработчик, что в настройках), поиск повторяется для текущей точки без записи в историю, а в уведомлении прямо сказано: километраж и сторона движения недоступны.
- Автоматической подмены данных нет: решение принимает пользователь, потому что локальный индекс построен из OSM (46 420 дорог, срез 21.10.2026) и не содержит официального километража (`no authoritative chainage; geometry length only`) и стороны движения. Проверка на точке 47.889183, 40.212364: локально находится «Дон» (код М-4) и 143 м до оси, километр — `null`; через СКДФ — «254 км + 187 м, справа по ходу».
- Тест: `tests/e2e/test_ui.py::test_road_service_failure_offers_local_source` — ошибка 502, наличие кнопки, переключение источника и повторный запрос с `use_local=true`.

## Общий лимит API выключен по умолчанию

- `ALBION_API_RATE_LIMIT` по умолчанию **0 (выключен)**: сервис работает локально или через VPN, а один сеанс работы с ползунком километража стоит десятки запросов (история, МСК, обратный геокодер). При значении 300 этот поток упирался в лимит, и `locate` начинал получать 429 — ошибка выглядела как отказ СКДФ, хотя СКДФ был ни при чём.
- Лимит сохраняется как настройка: `ALBION_API_RATE_LIMIT=300` включает его для публичного контура. Лимит входов (`ALBION_LOGIN_RATE_LIMIT`) и lockout после 5 неудач остаются включёнными всегда — они защищают от подбора пароля, а не от всплесков нагрузки.
- Тесты: `tests/test_security.py` — лимит выключен по умолчанию и не мешает серии запросов; включается и отдаёт 429 с `Retry-After`.
- Наблюдение по журналу (не исправлено): за минуту сбоя интерфейс зафиксировал одну и ту же точку ~95 раз (95 `POST /api/geocode/reverse`, 94 `POST /api/history`, 13 `POST /api/msk61`). Обычная работа ползунком такого не даёт — 30 нажатий ArrowRight и 10 тиков колеса дают одну фиксацию. Триггер ещё не найден; после выключения лимита шторм перестал быть фатальным, но дедупликацию фиксации стоит добавить отдельно.
