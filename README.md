# Albion Locator Autonom

Веб-приложение для определения ближайшей дороги Ростовской области по координатам или GPS-метаданным фотографий. Это описание относится к **активной сборке** `src/main.py` + корневой `static/index.html`; в репозитории также есть старые/копии (`static/main.py`, `src/main (Copy*).py`, `release/v4.2.1/` и `src/static/index.html`), которые не являются entry point этого запуска.

## Возможности

- Интерфейс «Вариант A»: левый фрейм с вкладками **Точка / Пакетный поиск / Сохранённое** и карточкой текущей точки (WGS84, МСК-61, адрес, район), карта в центре, правый фрейм с результатом дороги/километража, нижний статус-бар с быстрыми действиями. Название из источника СКДФ выводится слева в статус-баре, а в правом фрейме под «Из справочника» показывается справочное название дороги. Единый однострочный блок поиска (чекбокс активации, иконки Адрес/Координаты/Дороги, контекстное поле и кнопка-лупа) размещается сверху карты или в статус-баре — положение переключается в настройках. Поле показывает синхронизированные данные активной точки: название трассы, определённый адрес или координаты. В режиме координат по умолчанию отображается WGS84, а соответствующая зона МСК-61 определяется в фоне; переключатель систем предлагает только WGS84 и доступную МСК. При неверной выбранной зоне МСК поле остаётся пустым. Если активен призрак, его координаты показываются в скобках. Поиск только готовит черновик; точку фиксирует кнопка-лупа или Enter. Чекбокс активации не блокирует карту, но на время поиска блокирует пакетную загрузку и загрузку фото. Если фото уже загружены, поиск блокируется до нажатия «Очистить точку». В пакетном режиме поиск недоступен, новые точки не ставятся: правый фрейм работает с точкой, выбранной кликом по маркеру или строке списка; эту точку можно двигать ползунком официального километража.
- **Подписи точек:** кнопка 💬 в статус-баре включает постоянные подписи всех точек на карте — активной, пакетных и призрака.
- **Локальные дороги без chainage:** OSM не содержит официального километража, поэтому выбор такой дороги ставит точку на её ближайший фрагмент; статус явно сообщает, что км недоступен.
- **Тултип километража:** при наведении на ось дороги показывается только километраж на белом фоне, без иконок и стрелки; радиус срабатывания (4–40 px) настраивается в «Параметрах поиска дороги».
- Интерактивная Leaflet-карта: выбор точки, геолокация, история точек, закладки, тема и граница Ростовской области. OSM-подложка сейчас загружается онлайн. Кнопка 🎯 центрирует карту по активной точке, а в пакетном режиме — по всем загруженным точкам.
- Опциональные режимы (включаются в «Настройках»):
  - **Ссылка на точку**: состояние пишется компактно в hash — `#s=v1…` (base36, фиксированная ширина сегментов: координаты, зум, режим, вкладка, километр). Дорога восстанавливается по координатам, поэтому её код/имя в ссылку не попадают. Старые длинные ссылки `?lat=…&lon=…` продолжают читаться. Выключение режима удаляет параметры из URL.
  - **Множественный выбор точек** в пакетном режиме: чекбоксы, Shift/Ctrl-клик, массовый показ на карте и удаление.
  - **Детальный контур области**: локальная граница из `static/rostov_boundary_detailed.geojson` (1237 точек вместо 696 у упрощённого контура). Работает только при включённом локальном контуре; по умолчанию выключен.
  Эти режимы по умолчанию выключены и сохраняются в персональных preferences.
- **Установленные точки из XLS:** администратор загружает `.xls`/`.xlsx` в настройках; читаются только город, адрес, сторона и координаты (в одной ячейке или отдельными колонками широты/долготы). Кнопка **«Установленные»** в статус-баре показывает/скрывает зелёные точки, сгруппированные по координатам и адресу, и подгоняет карту. Повторный импорт обновляет существующие записи; список хранится в SQLite `users.db`.
- Выбор источника дорожных данных: текущий SKDF WFS online либо локальная база (если оператор отдельно импортировал её в `ALBION_GEO_DATA_DIR`). При выборе отсутствующей локальной базы запрос завершается ошибкой, без скрытого переключения на онлайн. Подложка карты переключается независимо: OSM онлайн, локальные растровые MBTiles или векторные тайлы MapLibre (z5–14, подписи на кириллице). Если установлена локальная подложка, она выбирается по умолчанию (`ALBION_DEFAULT_MAP_SOURCE` переопределяет); при ошибке/403 OSM карта автоматически переключается на локальные тайлы и показывает уведомление.
- Онлайн-поиск адресов через Yandex JavaScript API `SuggestView` и геокодирование выбранного варианта серверным Yandex Geocoder. Ключи JS API и Geosuggest передаются браузеру только после входа и должны быть ограничены доменом приложения; ключ Геокодера остаётся только на сервере. Локальный endpoint подсказок сохраняется отдельно, UI использует онлайн-режим.
- Онлайн-поиск только трасс и дорог (`М-4 Дон`, `Р-280`, `60К-80`, именованные объездные/подъездные дороги): браузерные подсказки SuggestView ограничиваются bbox контура области, затем сервер принимает только линейные дорожные объекты и проверяет регион, а при наличии кода — точное совпадение кода. Города, районы и обычные улицы в режиме «Дорога + км» не показываются. Выбранный результат ставит точку и запускает обычный поиск ближайшей дороги.
- Для трассы с кодом (`М-4`, `Р-280` и т. п.) под результатом загружаются официальные участки `start_km`/`finish_km` из слоя СКДФ `lyr_road_by_value_line`, ограниченные контуром Ростовской области. Участки подгружаются автоматически для точки, найденной на карте/по адресу/EXIF, если у ближайшей дороги есть код. Блок километража активен сразу: галка рядом с полем включена по умолчанию, и как только для точки определена дорога, ползунок, поле км, точка на карте, блок источника СКДФ и статус-бар синхронизируются в обе стороны — ввод/ползунок двигают точку вдоль трассы, а новая точка пересчитывает км по проекции на СКДФ. Автоматическое подключение километража не сдвигает уже выбранную точку: она переходит на ось только при явном действии (ползунок, ввод км, «Перейти» или кнопка-лупа). Галку можно снять, чтобы отключить синхронизацию. Если СКДФ не содержит километража для дороги (например, `А-280`), UI сообщает об этом явно. Для дорог без официальных участков (например, `60К-31`) строится приблизительная ось по геометрии OpenStreetMap через Overpass: рисуется оранжевая пунктирная линия, ползунок работает по относительной шкале `0…длина`, а клик по линии задаёт точку и километр. Для дорог без кода участки СКДФ сначала ищутся по названию — километраж у таких дорог тоже есть (например, «г. Шахты - г. Белая Калитва», 0–70.6 км). Если участков нет, ось строится по геометрии, которую вернул `locate` (СКДФ WFS), — это мгновенно и не зависит от Overpass; если геометрии нет, ось ищется в OSM по названию. Километры при этом относительные (0 — начало выбранного направления), а если ни геометрии, ни Overpass нет, ползунок остаётся выключенным с явной причиной. Километраж по локальной базе остаётся отдельным разделом.
- Локальное ядро offline search (`packages/offline_geo`) поддерживает contextual address suggestions, поиск дороги/кода и километража, nearest-road по импортированной базе. Генерируемая база не поставляется в репозитории; её подготовка/импорт — отдельный шаг.
- Явный предварительный калькулятор WGS84 ↔ МСК-61 зон 1–3 с выбором направления, зоны и профиля. По умолчанию выбран ГОСТ 51794-2008: Playwright-сверка с GeoBridge 18.10.2026 показала совпадение с `EPSG:6336101/102/103` в пределах 0.001 м вперёд и около 0.0003 м назад; профиль без сдвига датума расходится примерно на 105–114 м. Это сторонняя численная сверка, а не официальная геодезическая аттестация. Значок `?` у выбора зоны показывает опубликованное распределение кадастровых районов (с кодами) по зонам из статьи «Территория ГИС» от 30.07.2020 (обновление 17.08.2023); это не первичный документ Росреестра, поэтому при точных работах сверяйте исходную координатную ведомость. Результат по-прежнему помечается как предварительный и непригодный для кадастровой/геодезической точности без официальной контрольной верификации.
- Определение координат из EXIF одной фотографии и пакетная обработка нескольких фотографий.
- Снимки карты: настройки, локальное сохранение через браузер и/или API, автоудаление PNG старше семи дней.
- «Точка призрака» (кнопка 👻 в статус-баре): при активном официальном километраже ползунок двигает зелёный клон, не меняя исходную красную точку; «Перейти» фиксирует призрак и делает его красным. При повторном включении призрак сбрасывается к исходной точке. Карточка «Текущая точка» всегда показывает исходную красную точку; в режиме призрака его координаты и километр выводятся отдельной строкой в правом фрейме. При выключении призрака правый фрейм возвращается к исходной точке, а карта центрируется на ней. Стрелки клавиатуры управляют ползунком после фокуса в поле км, Tab-фокуса/клика по ползунку или клика по зелёному/красному маркеру; включение клавиатуры и колеса мыши настраивается в параметрах.
- Слежение за ползунком (кнопка 👁 в статус-баре и чекбокс в настройках): при движении ползунка или вводе километража карта следует за выбранной точкой (или активным призраком), сохраняя масштаб. Пока режим активен, клавиатурное управление картой отключено — перемещать её можно только левой кнопкой мыши. Кнопка «Перейти» дополнительно центрирует карту на выбранном километраже.
- Дискретный шаг километража: 5/10/50/100/500 м. Переключается кнопкой в статус-баре и селектором в настройках; под ползунком рисуются вертикальные штрихи выбранного шага и точки каждые 1000 м (для длинных трасс — локальная шкала вокруг бегунка).
- Локальный GeoJSON для границы с возможностью загрузки внешней геометрии через Overpass.
- Внешний режим может использовать Yandex Geocoder при отсутствии найденной дороги; локальный режим не вызывает Yandex. Ollama не используется для автоматической подстановки названия дороги.

## Архитектура и стек

- **Backend:** Python 3.11+, FastAPI, Uvicorn, Pydantic; `httpx` для сетевых запросов; Pillow и `piexif` для EXIF.
- **Frontend:** статическая страница HTML/CSS/JavaScript; Leaflet 1.9.4 и `dom-to-image-more` лежат в `static/vendor/` и отдаются локально. Клиентская логика находится в `static/index.html`.
- **Локальный поиск:** пакет `packages/offline_geo` использует SQLite/FTS5; `nearest_road` использует segment-level RTree-префильтр (schema v5), точная проекция выполняется в Python. Optional CLI умеет обновлять локальный Geofabrik PBF через `pyosmium-up-to-date` и импортировать его через polygon clip+osmium в SQLite snapshot. Требуются отдельные `osmium`/Python `osmium` tools. Данные/SQLite index/MBTiles не включены; импорт обязан пройти coverage QA перед production use.
- **Данные приложения:** `src/roads.py` — словарь дорог; `rostov_boundary.geojson` / `static/rostov_boundary.geojson` — граница; учётные записи, персональные настройки, рабочая сессия и закладки хранятся в SQLite `src/users.db` (`ALBION_USERS_DB`). MBTiles/SQLite offline data располагаются отдельно через `ALBION_GEO_DATA_DIR`, `ALBION_BASEMAP_MBTILES` (растр) и `ALBION_VECTOR_MBTILES` (вектор). Сборка векторной подложки описана в `deploy/vector/README.md`.
- **PostgreSQL:** установлен локально, но приложение/поисковый модуль его пока не используют; основной local index — portable SQLite.

### Поток обработки

1. Браузер отдаёт статическую карту с `/` и `/static/rostov_boundary.geojson`; выбор точки, ручной ввод или EXIF-фото формируют координаты.
2. `/api/locate` использует локальную базу при `use_local=true` (или `ALBION_OFFLINE=1` по умолчанию) и иначе запрашивает SKDF WFS. Локальный режим никогда не переключается на WFS автоматически.
3. После входа UI получает JS API и Geosuggest ключи через защищённый `/api/maps-config`, загружает `ymaps.SuggestView` в браузере и использует серверный `/api/address/online/geocode` для координат выбранного варианта. Ключ Геокодера в браузер не передаётся. Локальные `/api/address/suggest` и `/api/roads/search` остаются отдельными функциями SQLite index; готовый index не включён.
4. МСК-61 API конвертирует координаты по выбранным зоне и профилю, возвращает `preliminary_unverified` и предупреждение; установка точки требует дополнительного подтверждения. Геодезическую/кадастровую точность не гарантирует.
5. Персональные настройки, рабочая сессия, история и закладки хранятся в SQLite; общий `user_settings.json` содержит только настройки скриншота. Скриншоты сохраняет браузер. Выбранные источники карты/дорог и тема дополнительно кэшируются браузером.
5. Пакетный endpoint извлекает GPS из каждого файла и возвращает результаты пофайлово; UI может показать точки на карте и запрашивать дорогу для каждой отдельно.

## HTTP API

По умолчанию интерактивная документация FastAPI (`/docs`, `/redoc`) и `/openapi.json` закрыты. Для локальной разработки включите `ALBION_ENABLE_DOCS=1`.

| Метод и путь | Вход | Назначение / ответ |
|---|---|---|
| `GET /api/health` | — | Минимальный статус `{status: "ok"}`; **не** проверяет доступность внешних зависимостей. |
| `GET /metrics` | loopback или `X-Metrics-Token` | Prometheus-метрики HTTP, upstream-запросов, кэша, ретраев и аудита. Через reverse proxy задайте `ALBION_METRICS_TOKEN`. |
| `POST /api/auth/login` | JSON `login`, `password` | Вход; устанавливает HttpOnly cookie `albion_session`. |
| `POST /api/auth/logout` | cookie | Завершить сессию и очистить cookie. |
| `GET /api/auth/me` | cookie | Текущий пользователь. |
| `POST /api/auth/change-credentials` | JSON `current_password`, `login?`, `password?` | Сменить собственные логин/пароль. |
| `GET /api/users` | cookie администратора | Список пользователей. |
| `POST /api/users` | JSON `login`, `password`, `name`, `role` | Создать пользователя (`admin`/`editor`). |
| `PATCH /api/users/{id}` | JSON `login?`, `name?`, `role?`, `is_active?` | Изменить пользователя. |
| `POST /api/users/{id}/password` | JSON `password` | Сменить пароль пользователя. |
| `GET /api/audit` | cookie администратора, `limit?`, `offset?`, `action?` | Журнал входов, смен данных и действий с пользователями (без паролей и токенов). |
| `GET /api/installed` | cookie | Точки, импортированные из XLS: город, адрес, сторона, координаты. |
| `GET /api/installed/status` | cookie | Количество установленных точек. |
| `POST /api/installed/import` | multipart `file` (.xls/.xlsx), admin | Разобрать таблицу и добавить/обновить точки; повторный импорт не создаёт дубликаты. |
| `DELETE /api/installed` | admin | Удалить все импортированные точки. |
| `GET /api/screenshot-settings` | — | Прочитать настройки снимков из JSON (либо значения по умолчанию); `save_path` всегда возвращается как `screenshots`. |
| `POST /api/screenshot-settings` | JSON `delay` (1–60), `save_path`, `auto_enabled`, `local_boundary` | Изменить настройки; сервер принудительно фиксирует `save_path` в `screenshots`. |
| `POST /api/save-screenshot` | JSON `image` (PNG data URL/base64, ≤6 МБ), `filename` (имя `.png`) | Проверить и сохранить скриншот только в `src/screenshots`; удаляет старые PNG старше 7 дней. |
| `POST /api/exif` | multipart поле `photo` | Вернуть `{lat, lon}` из GPS EXIF; 400 при пустом/нечитаемом файле или отсутствии GPS. |
| `POST /api/locate` | JSON `lat`, `lon`, `radius`, `exclude_categories`, `use_local?` | Поиск ближайшей дороги. `use_local=true` требует установленный `offline_geo.sqlite3` и никогда не переключается на WFS. Внешний режим использует SKDF WFS; в нём `use_local=false`. |
| `GET /api/data-sources` | — | Доступность локальной SQLite/MBTiles и boolean-статусы источников/ключей (секреты не возвращаются). `fully_offline_ready` равен `true`, когда найден локальный индекс и хотя бы одна локальная подложка (растровая или векторная); сами данные в репозиторий не входят. |
| `GET /api/maps-config` | cookie | После входа возвращает browser-side Yandex JS API и Geosuggest keys с `Cache-Control: no-store`; **не** возвращает server-side `YANDEX_API_KEY`. Client keys следует ограничить доменом в кабинете Яндекса. |

## Авторизация

Вход в приложение обязателен: без действующей cookie-сессии показывается только форма входа, карта и ее данные скрыты. Форма подписана «АЛЬБИОН.Локатор / закрытый веб-сервис / вход по логину и паролю / их можно получить у Администратора». Гостевого входа нет, новые учётные записи создаёт только администратор. Все `/api/*`, кроме `/api/health` и `/api/auth/login`, требуют cookie-сессию. Логин по умолчанию: **`админ` / `альбион`**. При `ALBION_REQUIRE_PASSWORD_CHANGE=1` (по умолчанию) после первого входа, а также после сброса пароля администратором принудительно открывается окно смены пароля; закрыть его без смены нельзя. В обычном режиме собственный логин и пароль меняются по кнопке 👤 в нижней панели. Администратор в блоке «Пользователи» создает аккаунты с ролями `admin`/`editor`, меняет их логины и имена, отключает/включает пользователей и сбрасывает пароль. Редакторы не видят административное управление; проверка прав выполняется сервером.

Пользователи и сессии хранятся в SQLite `src/users.db` (путь можно переопределить через `ALBION_USERS_DB`). Пароли — PBKDF2-HMAC-SHA256 с солью; в базе хранятся только хэши. Cookie `albion_session` — HttpOnly, SameSite=Lax, срок 30 дней. Администратор может создавать пользователей и менять им логин, пароль, роль и активность; роль `editor` не имеет доступа к управлению пользователями.

Входы, неудачные попытки, смена своих данных и действия администратора с пользователями пишутся в таблицу `audit_log` (последние 5000 событий); пароли и токены туда не попадают. Администратор видит журнал в «Настройках → Журнал событий» или через `GET /api/audit`.

При работе через reverse proxy (например, CloudPub) Origin сверяется с `Host`/`X-Forwarded-Host`; дополнительные разрешённые источники можно перечислить через запятую в `ALBION_ALLOWED_ORIGINS`. Для TLS-прокси включите `ALBION_COOKIE_SECURE=auto` (использует `X-Forwarded-Proto`) или `always`. CSRF защищён double-submit cookie `albion_csrf` + заголовок `X-CSRF-Token`; UI добавляет заголовок автоматически. Вход ограничен rate-limit и lockout, все API — общим лимитом на IP. Подробности и шаблон nginx — `deploy/README.md`.

## Ключевые функции

`src/main.py`:

- `extract_exif`, `_dms_to_dd` — чтение GPS-тегов и перевод DMS в десятичные градусы.
- `_bbox_from_radius`, `_haversine`, `_bearing`, `_local_m`, `_project_on_line`, `_road_side_info` — геометрия и расстояния.
- `_wfs_getfeature` — запрос дорожных объектов WFS; upstream-ошибки возвращаются клиенту как контролируемый 502, а не как «дорога не найдена».
- `get_first_point` — извлечение первой координаты геометрии.
- `normalize_text`, `find_road_id_by_name`, `find_road_id_with_llm`, `format_road_names` — соответствие наименований справочнику, включая fuzzy и LLM пути.
- `get_yandex_road_name` — reverse geocoding.
- `load/save_settings`, `cleanup_old_screenshots` — файловая персистентность общих настроек; персональные настройки, рабочая сессия и закладки — в `src/auth.py` (SQLite).

`src/batch.py`: `extract_gps_safe`, `_dms_to_dd` и `batch_upload` реализуют пакетное чтение EXIF.

## Установка и запуск вручную

Требуются Python 3.11+ и `uv`. Из корня проекта:

```bash
uv venv .venv
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python -m uvicorn main:app --app-dir src --host 127.0.0.1 --port 8021
```

Интерфейс будет на <http://127.0.0.1:8021/>. Приложение также можно запустить как `python src/main.py`; прямой запуск также привязывается к loopback `127.0.0.1:8021`.

Переменные окружения можно задать в процессе сервера или в локальном корневом `.env` (он загружается через `python-dotenv`; в Git не добавлять). Нужны `YANDEX_JS_API_KEY` и `YANDEX_SUGGEST_API_KEY` для SuggestView, `YANDEX_API_KEY` — только server-side Geocoder/reverse-geocoding. JS API и Geosuggest ключи отправляются вошедшему браузеру через защищённый `/api/maps-config`, поэтому ограничьте их точным hostname приложения и соответствующими продуктами/квотами в кабинете Яндекса. `YANDEX_API_KEY` в браузер не передаётся. Адресный текст отправляется Яндексу. Не помещайте реальные ключи в HTML, документацию, Git или логи; после изменения `.env` перезапустите приложение. Ранее ключи были включены в историю исходников и вспомогательный `check_keys.py`; удаление fallback не отзывает их — рекомендуется вручную проверить/заменить у провайдера и удалить из публичной Git-истории при необходимости.

## Пользовательский systemd

В установленной локальной конфигурации используется unit `albion-locator-autonom.service`, virtualenv вне репозитория и порт 8021. Управление:

```bash
systemctl --user status albion-locator-autonom.service
systemctl --user restart albion-locator-autonom.service
systemctl --user stop albion-locator-autonom.service
journalctl --user -u albion-locator-autonom.service -f
```

Для этой учётной записи systemd lingering включён (`loginctl show-user alexice -p Linger` → `Linger=yes`), поэтому включённый user unit запускается после загрузки системы, до интерактивного входа.

## Логи, метрики и резервные копии

- **Логи.** `src/observability.py` настраивает JSON-логи в stderr (journald): время, уровень, `request_id`, метод, путь, статус, длительность, пользователь, upstream-сервис, ретраи и cache hit. Уровень — `ALBION_LOG_LEVEL`, формат — `ALBION_LOG_FORMAT=json|plain`. Каждый ответ содержит `X-Request-ID` (входящий заголовок сохраняется).
- **Метрики.** `GET /metrics` отдаёт Prometheus-текст. Без токена endpoint доступен только с loopback и отклоняет запросы с `X-Forwarded-For`; для сбора через nginx задайте `ALBION_METRICS_TOKEN` и передавайте его в `X-Metrics-Token`. В reverse proxy закройте `/metrics` от внешней сети.
- **Внешние вызовы.** WFS, Overpass и Yandex используют общий retry с ограниченным exponential backoff (429/5xx/timeout), WFS-страницы и ответы геокодера кэшируются в памяти с TTL. Настройки: `ALBION_UPSTREAM_RETRY_ATTEMPTS`, `ALBION_UPSTREAM_CACHE_TTL` (0 отключает кэш).
- **Резервные копии.** `python3 deploy/backup_data.py --dest /var/backups/albion-locator --keep 14` создаёт согласованный снимок `users.db` и офлайн-данных с `manifest.json`, SHA-256 и `PRAGMA integrity_check`; `--verify-latest` проверяет последний снимок. Шаблон daily timer — `deploy/systemd/albion-backup.{service,timer}`.
- **Обновление офлайн-данных.** `python3 deploy/update_offline_data.py --geo-dir /var/lib/albion/geo` скачивает PBF, собирает индекс и vector MBTiles в staging, проверяет целостность, сохраняет rollback-копию и атомарно заменяет рабочие файлы. Подробности — `deploy/README.md`.

## Рекомендации по безопасности, качеству и производительности

**Сначала устранить критичные риски до сетевой публикации:**

1. Удалить/отозвать опубликованные Yandex-ключи у провайдера (это действие не выполнялось); приложение читает ключ только из environment. Сервер слушает loopback; API требует cookie-сессию кроме health/login. При расширении доступа отдельно проверить security headers, `Secure` cookie за proxy и `ALBION_ALLOWED_ORIGINS`.
2. Приложение выдаёт только корневой UI и `/static/rostov_boundary.geojson`, не монтирует всю корневую `static/` и не публикует скрипты/бэкапы.
3. `/api/save-screenshot` игнорирует пользовательский путь, пишет в `src/screenshots`, принимает ограниченный basename и валидированный PNG до 6 МБ; уникальное имя создаётся эксклюзивно. Поддерживаемая HTML-настройка пути на UI только для чтения.
4. `/api/exif` ограничивает файл 12 МБ; `/api/batch/upload` — 50 файлов, 12 МБ на файл и 100 МБ на пакет. GPS EXIF проверяется на refs и географические границы; Pillow ограничен по размерам изображений.
5. `/api/locate` валидирует конечные координаты и радиус; выбор дороги использует расстояние до линейной геометрии, а ошибки WFS сообщаются как 502. Добавление rate limit остаётся рекомендацией для любого будущего сетевого развёртывания.

**Этап 1 (сеть/безопасность) — текущее состояние:** `Secure` cookie включается по HTTPS/`X-Forwarded-Proto`, добавлены CSRF/Origin-проверка, rate-limit, lockout, security headers и CSP, `/docs` закрыт. Осталось организационно: TLS/reverse proxy на LAN или туннель, ротация ключей Яндекса и ограничение их доменом, проверка `.env` 0600. Шаблон nginx и чек-лист — в `deploy/README.md`.

**Оставшиеся рекомендации по качеству и производительности:**

- WFS 2.0 `count/startIndex` на текущем публичном слое при малом bbox возвращал OWS `Cannot do natural order without a primary key`; capabilities также сообщает `PagingIsTransactionSafe=FALSE`. Поэтому paginated online request может завершиться 502; для полноценного offline покрытия нужен импортёр/сортируемый официальный feed или OSM-снимок. Не объявлять WFS snapshot полным без QA.
- Fuzzy matching теперь защищён от пустого текста и использует нормализацию кодов, однако неоднозначные длинные названия следует проверять на размеченной выборке и не полагаться на один порог `SequenceMatcher`.
- Официальные названия дорог формируются консервативным детерминированным сопоставлением; Ollama больше не используется для автоматической подстановки дорожного кода в ответы.
- JSON состояния теперь пишется атомарно и критичные read-modify-write операции сериализованы в пределах одного процесса. Для запуска нескольких worker/processes или более надёжного хранения перейти на SQLite.
- Добавить фиксированные версии/lockfile и включить CI на каждом push/PR (workflow `qa.yml` уже содержит pytest, bun и Playwright). Структурированные логи и `/metrics` добавлены; тесты покрывают геометрию, координаты/EXIF, request limits, Origin, скриншоты, allowlist ресурсов, WFS paging/ошибки, audit log, backup manifest и офлайн-пакет; внешние WFS/Yandex/Ollama в тестах намеренно не дергаются.



## Ограничения и риски текущего состояния

Это промежуточная версия локального поиска. Пакет предоставляет SQLite API и API/UI подключение, но клон не включает адресную/дорожную SQLite базу, OSM PBF или MBTiles; браузерные Leaflet/dom-to-image уже поставляются локально, но OSM-тайлы остаются сетевыми. PBF importer/clipping реализован в `packages/offline_geo`; штатное обновление с проверкой и откатом — `deploy/update_offline_data.py`. Поэтому выбор локального источника без установленного индекса/тайлов вернёт явную ошибку, а карта/внешний режим сохраняют сетевые зависимости. Для небольшого WFS bbox проверены `count/startIndex` совместно с `sortBy=id A`; без явного порядка WFS выдавал ошибку natural order. Полный областной экспорт, надёжность paging на объёме и право на bulk-кэш пока не подтверждены; официальный SKDF `geo_road_axis_lr` возвращает permission denied. МСК-61 конвертер предварительный: проекционная математика сверена с 48 независимыми векторами PROJ (`packages/offline_geo/tests/data/msk61_proj_control_points.json`), но официальная геодезическая аттестация и сверка с кадастровыми контрольными точками по-прежнему нужны. Границы проверки и порядок добавления официальных точек — `docs/msk61-control-points.md`. Пользовательская аутентификация включена, но перед LAN/Internet публикацией проверьте cookie `Secure`, proxy/origin и секреты.
