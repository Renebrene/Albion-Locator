# Albion Locator Autonom

Веб-приложение для определения ближайшей дороги Ростовской области по координатам или GPS-метаданным фотографий. Это описание относится к **активной сборке** `src/main.py` + корневой `static/index.html`; в репозитории также есть старые/копии (`static/main.py`, `src/main (Copy*).py`, `release/v4.2.1/` и `src/static/index.html`), которые не являются entry point этого запуска.

## Возможности

- Интерактивная Leaflet-карта на OpenStreetMap: выбор точки, геолокация, ручной ввод координат, история точек, закладки, тема и граница Ростовской области.
- Поиск дорожного объекта в заданном радиусе по данным SKDF WFS; исключение категорий, классификация и покрытие, сопоставление с локальным справочником `src/roads.py`, оценка километража и стороны дороги.
- Определение координат из EXIF одной фотографии и пакетная обработка нескольких фотографий.
- Снимки карты: настройки, локальное сохранение через браузер и/или API, автоудаление PNG старше семи дней.
- Локальный GeoJSON для границы с возможностью загрузки внешней геометрии через Overpass.
- Yandex Geocoder как fallback для названия улицы; Ollama как дополнительное сопоставление названия дороги со справочником.

## Архитектура и стек

- **Backend:** Python 3.11+, FastAPI, Uvicorn, Pydantic; `httpx` для сетевых запросов; Pillow и `piexif` для EXIF.
- **Frontend:** статическая страница HTML/CSS/JavaScript, Leaflet 1.9.4 и `dom-to-image-more` с публичных CDN; клиентская логика находится в `static/index.html`.
- **Данные:** `src/roads.py` — локальный словарь дорог; `rostov_boundary.geojson` / `static/rostov_boundary.geojson` — граница; настройки и закладки хранятся JSON-файлами рядом с `src/main.py`.
- **Нет:** БД, миграций, контейнера, CI-конфигурации и автоматизированного набора тестов в исходном проекте.

### Поток обработки

1. Браузер отдаёт статическую карту с `/` и `/static/*`; выбор точки, ручной ввод или загрузка EXIF-фото формируют координаты.
2. `/api/locate` ограничивает радиус диапазоном 10–5000 м, сохраняет последнюю координату, запрашивает до 50 объектов дороги у SKDF WFS по bbox, фильтрует кандидатов и сопоставляет имя с локальным справочником.
3. При необходимости вызывается Yandex Geocoder и/или Ollama; ответ содержит имя дороги и вычисленные положение проекции, сторону, расстояние/километраж.
4. Закладки и настройки пишутся в JSON-файлы; скриншоты сохраняются в заданную директорию. Геоистория, тема и часть состояния интерфейса ведутся браузером.
5. Пакетный endpoint извлекает GPS из каждого файла и возвращает результаты пофайлово; UI может показать точки на карте и запрашивать дорогу для каждой отдельно.

## HTTP API

Запущенный экземпляр публикует интерактивную документацию FastAPI по `/docs`, схему OpenAPI по `/openapi.json`.

| Метод и путь | Вход | Назначение / ответ |
|---|---|---|
| `GET /api/health` | — | Минимальный статус `{status: "ok"}`; **не** проверяет доступность внешних зависимостей. |
| `GET /api/screenshot-settings` | — | Прочитать настройки снимков из JSON (либо значения по умолчанию); `save_path` всегда возвращается как `screenshots`. |
| `POST /api/screenshot-settings` | JSON `delay` (0–60), `save_path`, `auto_enabled`, `local_boundary` | Изменить настройки; сервер принудительно фиксирует `save_path` в `screenshots`. |
| `POST /api/save-screenshot` | JSON `image` (PNG data URL/base64, ≤6 МБ), `filename` (имя `.png`) | Проверить и сохранить скриншот только в `src/screenshots`; удаляет старые PNG старше 7 дней. |
| `POST /api/exif` | multipart поле `photo` | Вернуть `{lat, lon}` из GPS EXIF; 400 при пустом/нечитаемом файле или отсутствии GPS. |
| `POST /api/locate` | JSON `lat` (−90…90), `lon` (−180…180), `radius` (10–5000, по умолчанию 2000), `exclude_categories` (по умолчанию `[6]`) | Поиск ближайшей дороги по расстоянию до линии. Возвращает `point`, `road` (геометрия, категория/покрытие, стартовый/финишный км) и `side` (может быть `null`). Некорректные значения отклоняются с 422; ошибка WFS — с 502. |
| `GET /api/bookmarks` | — | Получить список закладок. |
| `POST /api/bookmarks` | JSON `name`, `lat`, `lon` | Добавить закладку; сохраняется не более 50, новые — первыми. |
| `DELETE /api/bookmarks/{bookmark_id}` | ID в пути | Удалить закладку с указанным ID. |
| `POST /api/batch/upload` | multipart повторяющиеся поля `files` | Извлечь GPS из набора изображений; массив результатов с `filename`, `lat`, `lon`, `error`. |
| `GET /` | — | Основной HTML-интерфейс. |
| `GET /static/rostov_boundary.geojson` | — | Единственный явно доступный статический ресурс; прочие файлы корневого `static/` не раздаются через это приложение. |

Ответ `/api/locate` включает геометрию выбранной дороги для векторного отображения в интерфейсе.

## Ключевые функции

`src/main.py`:

- `extract_exif`, `_dms_to_dd` — чтение GPS-тегов и перевод DMS в десятичные градусы.
- `_bbox_from_radius`, `_haversine`, `_bearing`, `_local_m`, `_project_on_line`, `_road_side_info` — геометрия и расстояния.
- `_wfs_getfeature` — запрос дорожных объектов WFS; upstream-ошибки возвращаются клиенту как контролируемый 502, а не как «дорога не найдена».
- `get_first_point` — извлечение первой координаты геометрии.
- `normalize_text`, `find_road_id_by_name`, `find_road_id_with_llm`, `format_road_names` — соответствие наименований справочнику, включая fuzzy и LLM пути.
- `get_yandex_road_name` — reverse geocoding.
- `load/save_settings`, `load/save_bookmarks`, `cleanup_old_screenshots` — локальная JSON/файловая персистентность.

`src/batch.py`: `extract_gps_safe`, `_dms_to_dd` и `batch_upload` реализуют пакетное чтение EXIF.

## Установка и запуск вручную

Требуются Python 3.11+ и `uv`. Из корня проекта:

```bash
uv venv .venv
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python -m uvicorn main:app --app-dir src --host 127.0.0.1 --port 8019
```

Интерфейс будет на <http://127.0.0.1:8019/>. Приложение также можно запустить как `python src/main.py`; прямой запуск также привязывается к loopback `127.0.0.1:8019`.

Переменные окружения: `OLLAMA_HOST` (по умолчанию `http://localhost:11434`), `OLLAMA_MODEL` (по умолчанию `qwen2.5:3b`), `YANDEX_API_KEY` (необязательный ключ геокодера). Геокодер выключен, пока переменная окружения не задана. Защитите ключ и не публикуйте его в README, Git или логах. Ранее ключи были включены в историю исходников и вспомогательный `check_keys.py`; удаление fallback не отзывает эти ключи — рекомендуется вручную проверить/заменить их у провайдера и удалить из публичной Git-истории при необходимости.

### Запуск тестов

```bash
uv pip install --python .venv/bin/python -r requirements-dev.txt
.venv/bin/pytest -q
```

## Пользовательский systemd

В установленной локальной конфигурации используется unit `albion-locator-autonom.service`, virtualenv вне репозитория и порт 8019. Управление:

```bash
systemctl --user status albion-locator-autonom.service
systemctl --user restart albion-locator-autonom.service
systemctl --user stop albion-locator-autonom.service
journalctl --user -u albion-locator-autonom.service -f
```

Для этой учётной записи systemd lingering включён (`loginctl show-user alexice -p Linger` → `Linger=yes`), поэтому включённый user unit запускается после загрузки системы, до интерактивного входа.

## Рекомендации по безопасности, качеству и производительности

**Сначала устранить критичные риски до сетевой публикации:**

1. Удалить/отозвать опубликованные Yandex-ключи у провайдера (это действие не выполнялось); приложение теперь читает ключ только из environment. API локальное: изменяющие запросы с `Origin` допускаются только с `http://127.0.0.1:8019` и `http://localhost:8019`, прямой запуск и systemd слушают только loopback. При расширении доступа до LAN сначала добавьте аутентификацию/авторизацию и отдельно задайте минимальную политику origins.
2. Приложение выдаёт только корневой UI и `/static/rostov_boundary.geojson`, не монтирует всю корневую `static/` и не публикует скрипты/бэкапы.
3. `/api/save-screenshot` игнорирует пользовательский путь, пишет в `src/screenshots`, принимает ограниченный basename и валидированный PNG до 6 МБ; уникальное имя создаётся эксклюзивно. Поддерживаемая HTML-настройка пути на UI только для чтения.
4. `/api/exif` ограничивает файл 12 МБ; `/api/batch/upload` — 50 файлов, 12 МБ на файл и 100 МБ на пакет. GPS EXIF проверяется на refs и географические границы; Pillow ограничен по размерам изображений.
5. `/api/locate` валидирует конечные координаты и радиус; выбор дороги использует расстояние до линейной геометрии, а ошибки WFS сообщаются как 502. Добавление rate limit остаётся рекомендацией для любого будущего сетевого развёртывания.

**Оставшиеся рекомендации по качеству и производительности:**

- Проверить влияние `maxFeatures=50` и добавить корректную пагинацию/сортировку WFS, если актуальный слой может вернуть более 50 кандидатов. Проекция рассчитана в локальной плоской аппроксимации; проверить расстояния и километраж multipart геометрий на контрольных точках.
- Fuzzy matching теперь защищён от пустого текста и использует нормализацию кодов, однако неоднозначные длинные названия следует проверять на размеченной выборке и не полагаться на один порог `SequenceMatcher`.
- Ollama работает через async HTTP; при высокой конкуренции стоит ввести semaphore и использовать общий pooled client через lifespan. Кэш ограничен 512 ключами, но не имеет TTL.
- JSON состояния теперь пишется атомарно и критичные read-modify-write операции сериализованы в пределах одного процесса. Для запуска нескольких worker/processes или более надёжного хранения перейти на SQLite.
- Добавить фиксированные версии/lockfile, структурированный `logging` вместо `print`, CI и браузерные end-to-end тесты. Текущие pytest-тесты покрывают геометрию, координаты/EXIF-проверку, request limits, Origin, сохранение скриншотов, allowlist ресурсов и WFS-ошибки; внешние WFS/Yandex/Ollama намеренно не дергаются.



## Ограничения и риски текущего состояния

Это исследовательская версия; тесты теперь покрывают основные регрессии, но не заменяют end-to-end проверку реального WFS и браузеров. Зависимости всё ещё без lockfile. Сервер рассчитан на localhost и не имеет пользовательской аутентификации — не публиковать API в LAN/интернет напрямую. `/api/health` — только простой liveness endpoint и не гарантирует доступность WFS, Yandex или Ollama.
